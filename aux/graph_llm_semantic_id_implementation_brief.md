# graph_llm 改造说明：融合文本、评分与流行度的并行 Semantic ID 推荐

本文可以直接交给代码修改模型。它是一份待实现、待验证的研究方案，不代表已经取得性能提升。当前任务是改造代码并完成有限验证，不默认启动完整训练或大规模调参。

## 1. 修改目标与总体流程

项目路径：`/home/panqingwei/codesofpqw/LLMUserBias/graph_llm`。

请先阅读项目实际代码及适用的 AGENTS.md，再按本文改造。优先修改现有图、selector、评论投影和 LLM 流程，不在旁边另建一套独立推荐器。

目标：

- 推荐路径采用 `GNN → selector`：GNN 编码用户历史，selector 直接预测商品编码；LLM 仅负责选定商品后的解释生成。
- 文本向量模型统一使用 `FacebookAI/roberta-base`。
- 商品 Semantic ID 确实包含文本、rating 和交互流行度；不能只在 prompt 或损失权重中使用后两者。
- 文本码固定为 4 位，加上评分码、流行度码各 1 位，完整 SID 为 6 位；保留并行预测以及 RPG 式缓存打分和商品图搜索，不再以长 ID 为本方案目标。
- 现有图网络和 selector 同时接受推荐、解释相关监督。
- 支持更换解释 LLM，固定商品编码及信息来源，避免分词器改变整套图；推荐推理不依赖解释 LLM。

完整流程：

```text
离线准备：
商品标题与描述 → 冻结的 RoBERTa → 4 位文本编码
预先可用的评分统计 → 评分编码
预先可用的交互人数 → 流行度编码
三组编码组成固定商品 SID，并建立商品邻接索引

推荐阶段：
用户历史商品、个人评分、评论片段
→ 现有图网络整理历史信息
→ GNN 内部的图读出得到用户表示
→ 改造后的 selector 同时预测 6 个 SID 位置
→ 缓存分数，在真实商品图上搜索
→ 推荐列表

解释阶段：
选中商品 + 允许使用的用户/商品历史信息
→ 同一图网络和 selector 选择相关片段
→ 现有评论压缩与输入适配接口
→ 可替换的 LLM 生成解释
```

## 2. 先区分两种 rating

**商品 SID 中的 rating：商品在统计快照中的历史评分汇总。** 它对所有用户一致，保证同一商品在同一编码版本下有固定 SID。

**历史交互中的 rating：某个用户已经给某件商品打过的个人分数。** 它随交互进入用户表示，告诉模型这个用户的具体态度，但不改变候选商品的固定 SID。

例如：电影 A 的历史平均评分是 4.3，用户 U 曾给它 2 分。A 的商品 SID 使用历史汇总分，U 的历史记录同时保留个人的 2 分。

不要把用户尚未给目标商品打出的分数用作输入；不要按每个用户的个人评分给同一商品制作不同的候选 SID。

## 3. 数据、统计快照与泄漏约束

### 3.1 保留原始字段

保留 `raw_user`、`raw_item`、原始评分、评论原文、划分来源、样本编号，以及原始数据存在的时间戳。

当前数据构建代码有 rating 减 1 的处理。请明确记录评分尺度，避免重复减 1；不能仅根据当前子集的最小值猜测评分本来是 1～5 还是 0～4。缺失评分单独标记，不能自动当作最低分。

### 3.2 初版使用固定统计快照

SID 一旦包含评分与流行度，就会涉及统计时间。初版采用固定快照，不在每个 epoch 或验证/测试阶段重新编码。

**仅说“使用训练集统计”还不够：如果当前训练目标自己的评分已经进入商品 SID，也可能把答案间接带进模型。** 初版采用下面的明确协议：

1. 优先使用已有的、早于推荐训练目标的历史统计集合。
2. 若没有，在原训练集内部划出统计校准集 `D_calib` 和推荐训练目标集 `D_rec`。建议初始校准比例 20%，开放参数；这是工程起点，不是最优比例。
3. 有可靠时间戳时，使用训练时期较早的一段作为校准集，剩余较晚事件作为推荐训练目标；整个协议应保证输入不来自预测时刻之后。
4. 无时间戳时，按固定随机种子、以用户—商品对为分组单位划分，重复记录不跨组；将任务明确标为静态推荐，不声称是严格时间顺序推荐。
5. 校准记录可作为历史输入，但不作为本轮推荐/解释监督目标。评分、流行度、分桶阈值和文本量化器只在校准集合及其允许使用的商品元数据上拟合。
6. 原验证/测试划分文件不覆盖。比较方法都使用相同的校准/训练目标划分，报告实际样本量及这一协议与原始实验的差别。

这一划分减少了用于监督的训练目标，但能明确分离“已知统计”与“待预测事件”。不要为了避免这个代价，悄悄恢复为含目标评分的统计。

目标商品若不在统计快照中，仍可用其在推荐时已公开的元数据通过固定量化器编码；评分、流行度使用下文规定的未知/零观测编码。

初版测试历史默认只使用训练范围内的允许信息，不自动并入验证评论。若以后采用在线更新历史的协议，应单独实现和报告；更新历史不等于偷偷重算商品 SID。

训练/验证/测试的输入图和画像都不得使用当前目标评论、目标个人评分或目标 feature 标签。有时间戳时还必须逐样本排除未来历史。已有画像缓存不能因为文件名叫 train 就直接认为安全，需核对来源。

## 4. RoBERTa 文本向量

统一使用 `FacebookAI/roberta-base`，加载基础编码模型，读取隐藏状态；不使用 masked-LM 的词表预测 logits 作为文本向量。

- 商品输入默认是标题和描述；不把目标评论拼入商品文本。
- 评论/图节点输入为允许使用的原文句子或短片段。
- 初版冻结 RoBERTa，使用 eval 模式，输出 768 维向量。
- 本方案选择 attention-mask mean pooling：只平均有效内容位置，排除 padding 和特殊符号，再做 L2 归一化。全空文本需有确定的缺失表示和标记，不能除以零。
- 最大输入长度初始为 512，开放参数，处理方式写入缓存。保留大小写。
- RoBERTa 是基础预训练编码器，以上 pooling 是本方案的选择，不声称它是已经优化好的通用句向量模型。
- 不允许在加载失败时静默退回 Qwen embedding 或解释 LLM 的词向量。

缓存至少包含模型名称/版本、tokenizer、pooling、截断方式、文本内容摘要。向量独立于解释 LLM，可在更换解释模型时复用。

## 5. 分组构造 Semantic ID

初版采用分组编码，而不是把两个标量随意拼进 768 维向量后一起量化。这样能确保 rating/popularity 真正进入 ID，又便于控制其影响。

```text
SID(i) = [文本码 1, 文本码 2, 文本码 3, 文本码 4, 评分码, 流行度码]
```

本版固定 `m=4`，每个文本位置默认 256 个码字；评分、流行度各占一位。因此两组统计码均启用时，总长度为 6。关闭其中一组后为 5 位，两组都关闭时为 4 位。本版不安排增加文本码长度的实验。

每个位置拥有自己的类别空间。文本第一位的 12 与第二位的 12 不共用类别身份。SID 不使用解释 LLM 的自然语言 token ID。

### 5.1 文本码

对校准商品的 RoBERTa 向量拟合 OPQ + PQ，随后固定变换与量化码本，为商品生成文本编码。可使用 Faiss。

768 维向量经 OPQ 变换后分为 4 段，每段 192 维，各自量化得到 1 个文本码。固定随机种子、训练采样和码本版本。小样本不能在训练向量少于聚类中心数时硬训练；smoke 保留 4 个文本位置、使用单独的小码本配置，不能静默改变正式实验的码本大小。

### 5.2 评分码

先在校准集中按用户—商品对去重：有时间戳取快照内最后一次评分，无时间戳对重复评分取均值。只对有效评分计数。

对商品 i 计算平滑均分：

```text
smooth_rating_i = (sum_rating_i + alpha * global_mean_rating)
                  / (n_valid_rating_i + alpha)
```

`alpha` 初始为 10，开放参数。全局均分也只来自校准集。

- 无有效评分：评分码为 0，含义是未知，不是差评。
- 有评分：按声明的原始评分范围归一化到 [0,1]，均匀分成 8 桶，编码为 1～8；上端点确定地落入第 8 桶。
- 共 9 个评分类别。若校准集完全没有有效评分，全部标未知，记录原因，不能捏造均分。

保存原始均分、平滑均分、有效评分人数及评分码，便于审计。初版不引入额外的评分预测大模型。

### 5.3 流行度码

定义流行度为校准集中交互过商品 i 的不同用户数：

```text
n_i = count_distinct(raw_user | raw_item = i)
p_i = log(1 + n_i)
```

不是评论 token 频率，也不是商品文案中“热门”一词出现的次数。

- `n_i=0`：流行度码为 0，表示快照中零观测。
- 对已观测商品的 `p_i`，用校准商品等权计算 8 分位桶，编码为 1～8。
- 保存阈值与边界取值规则；相同计数必须得到相同编码。重复分位点可能产生空桶，应确定性处理并记录，不用随机排名拆开相同计数。

评分与流行度表示商品的已知状态，不应硬编码成“评分越高或越热门，推荐分数就越高”。是否适合当前用户由模型学习。

### 5.4 编码版本与碰撞

保存 `raw_item → SID` 映射、统计快照、量化参数、评分范围、分桶阈值和内容摘要。更换解释 LLM 时复用同一版本。

不同商品即使 SID 相同，也保留独立商品节点。初版同分按稳定商品编号处理并报告碰撞率；不能直接合并商品或偷偷加入逐位生成的唯一编号。碰撞严重时先检查编码分布，并在验证集比较更大码本；保持本版 4 个文本码的要求，不自动加长 ID。

## 6. 用户历史与原有图的融合

用户历史的每条记录至少保留：

```text
历史商品 SID + 该用户已知的个人 rating + 历史顺序/时间信息 + 评论片段
```

个人 rating 可归一化后投影或使用评分 embedding，缺失值单独表示。它是历史记录的属性，不修改候选商品 SID。历史流行度初版使用同一固定快照，避免无意混入未来统计。

保留具体历史商品。每件历史商品的 SID 码向量可聚合成商品节点表示，同时保留商品身份、个人评分以及可用的时间/位置特征和交互连接。先让 GNN 编码这些信息，再读出用户表示；不能一开始只平均整段历史，丢掉商品和顺序信息。无可靠时间戳时按静态图处理，不人为声称具备时序能力。推荐路径不将这些历史送入 LLM。

修改现有图：

- 节点用稳定的文本片段/短语编号，并保留原文、来源商品、来源用户与时间。
- 优先利用已有评论句子和短片段，不以引入另一个复杂抽取系统为前提。
- 连接片段、历史商品及其编码；评分和流行度保留类型信息，不能都当普通词共现。
- 使用节点类型及数值/关系表示区分信息；共现并不等于用户喜欢，负面表达不能丢失。
- 在受控的局部图上复用现有 GNN 主干。当前 selector 中存在稠密图运算，不能每个用户都构造全商品或全部码字的稠密图。
- 图节点不以某个解释 LLM 的 token 编号为主键。解释侧需要 token 位置时，通过原文及当前 tokenizer 重新映射。

## 7. GNN 直接连接 selector，LLM 仅用于解释

推荐主干固定为 `GNN → selector`，去掉原方案中的 LLM 用户编码步骤和 `LLM → selector` 输出适配层。初版图隐藏维度可设为 256，并开放配置。

GNN 先编码用户局部图，再使用带有效节点 mask 的可学习图读出得到用户向量，例如在 GNN 内部做注意力池化。读出仅依赖已有历史，不以未知目标商品或 LLM 隐藏状态作为查询。空历史采用可学习的缺省用户表示或明确的训练集先验，保证不产生 NaN。图读出是现有 GNN 的一部分，不另建用户 LLM 编码器。

扩展原 selector，让它直接根据 GNN 的用户表示，同时计算 4 个文本编码位置、评分位置、流行度位置的 logits；全部位置在同一次批量输出中完成。

一个可实现的打分形式是：

```text
H_u = GNN(用户局部图)
g_u = Readout(H_u, 有效节点 mask)
q_j = 当前编码位置 j 对 g_u 的小型投影
logit[j,c] = q_j 与该位置候选码向量 e[j,c] 的匹配分数
```

同一份 g_u 供全部位置使用，主要逻辑共享，位置投影可以独立。默认输出形状为文本 `[B,4,256]`、评分 `[B,9]`、流行度 `[B,9]`，共 6 组分类结果；关闭某组统计码时同步去掉对应输出。

量化码本和商品编码固定；分类用码向量、GNN、图读出和 selector 可以训练。这些可训练参数不应与固定量化中心混为一谈。

推荐阶段不加载、不调用解释 LLM，LLM 前向次数为 0；只进行一次用户局部图编码和 selector 并行打分。不要为了兼容旧入口而先构造 LLM 用户表示，也不先生成画像或思维链。纯推荐入口应能在未提供解释 LLM 权重的情况下独立训练和推理；固定 RoBERTa 的文本向量编码或缓存读取仍按需执行。

推荐损失必须能通过 logits 反传到 selector、分类用码向量、图读出和 GNN，不经过解释 LLM。现有固定 hard Top-K token bonus 不能替代这条训练路径。

解释阶段仍复用现有评论压缩与 `图/文本表示 → LLM 输入` 适配接口，为不同解释 LLM 设置相应输出维度；不再需要 `LLM → selector` 的适配。图和商品语义不依赖解释 tokenizer。更换解释 LLM 时，在固定推荐 checkpoint、SID、图数据和搜索随机种子的条件下，推荐分数与排序应保持不变，只重新适配解释接口及 LLM 的任务参数；不承诺解释模型零训练切换。

## 8. 统一的训练目标和商品分数

三组编码分别计算概率，推荐损失为：

以下文本位置 j 均取 1～4；保持对 4 个位置取平均。

```text
L_sid = mean_j CE(text_logits[j], target_text_code[j])
        + lambda_rating * CE(rating_logits, target_rating_code)
        + lambda_pop * CE(pop_logits, target_pop_code)
```

初始建议 `lambda_rating=0.2`、`lambda_pop=0.1`，仅作为可配置起点，最终用验证集选择。未知/零观测是明确类别，不伪造为低评分，也不随意跳过其候选评分项。

推理时使用一致的商品打分：

```text
S(u,i) = mean_j log P(text_code[i,j] | u)
         + lambda_rating * log P(rating_code[i] | u)
         + lambda_pop * log P(pop_code[i] | u)
```

这是用于排序的分数，不把它未经归一化就称作全商品空间中的概率。

这样 rating/popularity 既存在于商品 ID，又实际参与训练与解码。不能只把两位写进缓存却在候选打分时忽略。

联合目标：

```text
L_total = L_sid + lambda_explain * L_explain + lambda_selector * L_evidence
```

解释生成、feature/tail 加权尽量复用当前实现并开放开关。不要一开始新增大量对比损失、因果损失或强化学习。

支持先独立训练 `GNN → selector` 的推荐模式，再训练解释模块。联合训练时，`L_sid` 只更新推荐参数；`L_explain` 更新解释 LLM/输入适配参数，是否继续更新共享 GNN/selector 由显式冻结开关控制。若解释监督只通过不可微的 hard Top-K 选择文本，不能声称它已向 GNN/selector 反传；需要依靠显式节点监督或可微表示路径训练共享部分。比较不同解释 LLM 时固定推荐参数；若联合训练改变了这些参数，必须重新评估推荐效果，不能把它当作仅替换解释模型。

任务口径必须明确：初版默认预测观测交互，以便与 RPG 对照；这不等于把每次交互解释成“喜欢”。若改为正反馈推荐，单独配置原始评分阈值、同步改变所有基线和评估目标；低评分记录仍可作为历史输入。

## 9. RPG 式商品图搜索

用固定商品文本语义表示建立稀疏近邻索引。初版邻居主要按 RoBERTa 文本相似性选取，防止仅因评分相同或同样热门，把语义无关商品连成大团。评分、流行度已通过完整 SID 参与查询打分。

商品邻接索引和用户局部 GNN 的职责不同：前者负责搜索，后者负责学习用户表示。可以共享商品与编码数据，但不要把二者混成一次全图神经计算。

推荐时：

1. 一次计算并缓存全部编码位置的 log-probability 表。
2. 从真实商品中选择初始候选，混合历史邻居与少量随机入口，固定随机种子。
3. 扩展候选的图邻居，使用上节 S(u,i) 查表打分。
4. 去重并保留高分候选及已访问状态；包含旧候选，避免丢失已有高分结果。
5. 迭代有限轮数，返回 Top-K。默认排除已交互商品，并明确是否允许重复消费。

整个推荐阶段都不运行解释 LLM；图搜索只查缓存，不重新编码用户图，也不逐候选生成解释。6 个位置各自概率最大的码不能直接拼接成最终商品；搜索状态必须对应真实商品节点。

虽然文本码缩短为 4 位，仍采用完整 SID 各位置并行预测和商品图搜索，不改回逐位前缀解码。此处借鉴 RPG 的并行与缓存搜索机制，不声称本版拥有长 ID 的表达能力或未经验证的速度优势。

必须保留利用同一张分数表进行全量商品评分的基准模式，测量近似搜索漏掉多少高分商品。图索引、SID 表随商品数量增长，不声称总存储为常数。

## 10. 解释生成

选定商品之后，才为解释读取它的可见文本与允许使用的评论；复用图网络和 selector，选择与用户历史相关的原文片段，经现有压缩/输入适配接口交给解释 LLM。该阶段可以针对选定商品整理局部图和片段，但不能将其结果反过来用于候选搜索的打分。

此处“依据”就是有出处的用户评论、商品描述或历史评价，不是把某个潜在码字强行翻译成属性。

- 用户个人低评分不能被忽略后生成全是赞美的画像。
- 高平均评分、热门不自动等于用户喜欢。
- 不能因为两件商品共享编码，就把另一件商品的特点移过来。
- 不使用目标个人评分或目标评论作为解释输入。
- 只为需要展示的商品生成解释，不给整个搜索候选集生成文本。

解释仍逐词生成，计时与推荐阶段分开。推荐耗时包含所需的文本编码/缓存读取、GNN、selector 和图搜索，不包含解释 LLM；单独报告缓存冷/热状态。共享参数不自动证明解释忠实于排名决策，需在评估中检查。

## 11. 改造位置与缓存

请结合实际代码组织修改，以下是主要入口，不要求机械拆成固定新模块：

- `graph_llm/dataload/embeddings.py`：增加/切换冻结 RoBERTa，明确 pooling，取消新模式下静默回退。
- `graph_llm/dataload/legacy_data.py`、`dataloader.py`、训练入口的数据构建：保留原始评分与时间，提供校准/训练目标划分和历史表示。
- `graph_llm/models/token_graph.py`：使用稳定文本节点与商品/编码关系，避免绑死 LLM token ID。
- `graph_llm/models/selector.py`：复用 GNN，加入图读出，直接完成 4 个文本位置及评分/流行度位置的并行打分，并保留解释节点打分。
- `graph_llm/models/model.py`：分离不依赖 LLM 的推荐前向与可替换 LLM 的解释生成；只在解释路径保留图/评论输入适配。
- `graph_llm/train/trainer.py`：新训练目标、推荐评估、生成评估及 checkpoint 选择。
- `graph_llm/config/args.py`：新增参数与明确默认值。

新增 SID 量化、统计和邻接索引辅助文件是允许的；避免复制完整数据管线和第二套推荐网络。保留原解释模式作为可对照的运行选项。

缓存 fingerprint 应包含：数据划分/快照、rating 尺度及去重规则、流行度口径、分桶阈值、RoBERTa 版本/pooling、文本摘要、量化参数/种子、4 位文本码及启用的统计码、图构建参数。推荐向量/查询缓存若持久化，还需记录 GNN/selector checkpoint 与历史快照，不能复用旧模型的用户分数。解释相关缓存另含 LLM 模型与 tokenizer 标识；已有其他长度的 SID、邻接索引及依赖其编码的数据必须验证版本后重建，不能直接截断旧 SID。

输入向量缓存、固定 SID 缓存与每次查询的分数缓存是三件不同的东西，不能混用。

## 12. 参数与实验开关

至少开放以下设置，命名可按项目风格调整：

- 解释 LLM 路径（纯推荐模式不要求提供）、RoBERTa 路径、运行设备与 embedding 设备。
- `text_sid_length=4`（本版固定并校验）、`text_codebook_size`、量化随机种子。
- `use_rating_sid`、`use_popularity_sid`、`use_history_rating`。
- 评分原始范围、平滑 alpha、分桶数、统计快照/校准比例。
- `lambda_rating`、`lambda_pop`、`lambda_explain`、`lambda_selector`。
- 纯推荐/带解释模式，以及解释训练是否冻结推荐参数的显式开关。
- 图节点预算、邻居数、候选数、搜索轮数、精确/图搜索模式。
- 序列/静态任务模式、是否允许重复推荐、正反馈任务阈值。
- `smoke_device` 与最大 smoke batch 数。

SID 关闭某组时，同时关闭该组的目标、输入和打分；历史个人 rating 保留独立开关，以区分商品评分编码与个人反馈的作用。

## 13. 验证和实验要求

先完成实现与两批 smoke，再交付运行说明；不要默认启动全量训练。

必须做有实际意义的检查：

1. **数据隔离**：保持允许历史不变，修改验证/测试目标评论和个人评分，不应改变 SID、统计快照或推荐输入。修改 D_rec 的目标评分也不能改变 D_calib 构造的固定 SID。
2. **rating/pop 真正进入编码**：在独立受控样例中分别改变快照评分和交互人数，跨过分桶边界时只有相应编码组改变，文本码保持不变。
3. **跨 LLM 稳定性**：固定推荐 checkpoint、历史、图和搜索随机种子，更换解释 tokenizer/LLM 后，稳定节点、固定 SID、推荐分数和排序不变；只检查解释侧输入适配维度随 LLM 正确调整。
4. **并行与梯度**：纯推荐模式不提供 LLM 权重也能工作；整个推荐阶段解释 LLM 前向次数为 0。一次用户 GNN 编码后并行输出 `[B,4,256]`、`[B,9]`、`[B,9]`（默认配置）；`L_sid` 给 GNN、图读出、selector 和分类码向量提供预期梯度，不给解释 LLM 梯度。图搜索不触发 GNN 或 LLM 的额外前向。
5. **合法检索**：输出全部为真实商品；编码碰撞、空历史、缺失评分、零观测流行度、重复分桶边界都可处理。
6. **统一评分**：图搜索访问到的同一商品分数与精确查表模式一致。近似搜索不要求与精确 Top-K 完全一致，但必须报告其恢复率。
7. **端到端 smoke**：总共取同样的 2 个 batch，先验证不加载解释 LLM 的推荐训练/推理，再用同两批数据验证解释路径；不跑完整 epoch，不把只有 mock 的检查当作真实模型 smoke。smoke 始终保留 4 个文本位置，可使用较小的独立测试码本。若真实模型 smoke 受资源限制，明确报告未验证部分。

正式实验报告：Recall/NDCG、商品覆盖率、推荐商品平均流行度、按快照流行度分组的效果、解释指标、解释来源支持度，以及推荐耗时/解释耗时/总耗时、显存和索引大小。

至少保留文本 SID、文本+rating、文本+popularity、三者同时使用四种消融，完整长度分别为 4、5、5、6，文本部分始终为 4 位。比较这些组时保持历史个人评分等其他设置一致，再单独消融历史评分。流行度分桶增加后不能只报告整体 NDCG，掩盖长尾推荐明显下降。

新增模式以验证集推荐指标作为主要 checkpoint 选择依据，另行报告解释质量，不继续仅按 FMR 选择所谓“最佳推荐模型”。对比 RPG 时统一数据、统计快照、元数据来源、任务定义和调参条件。
